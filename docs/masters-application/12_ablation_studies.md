# Ablation Studies

**Status: two real, small-scale ablations run (session 2); no large-scale
study yet.** See `04_hypotheses.md` for what each supports. Raw outputs:
`research/ablations/memory_ablation.json`,
`research/ablations/critic_ablation.json` - both generated by
`backend/scripts/run_ablation_memory.py` and
`backend/scripts/run_ablation_critic.py`, which call the platform's actual
production code (`services.memory.queries.find_duplicate_experiment`,
`services.critic.checklist.critique_hypothesis`/`critique_experiment_config`),
not a re-implementation of it.

**What makes these "real but small":**
- Each is n=1: one constructed project/scenario, not a population of many
  researchers' or agents' proposed experiments.
- The "off" condition for the critic ablation is *modeled* (what would
  happen if the checklist call were removed from the API), not literally
  deployed as an unsafe code path - deploying an actually-unsafe path just
  to measure it would violate the platform's own safety principles.
- Both explicitly carry a `"caveat"` field in their JSON output stating
  this scope limitation, rather than letting the "finding" field overclaim.

**What a proper version of these studies (Sections 35/36/62/63) would still
need:**
- Grounding ablation (Experiment 1, Section 61): compare an ungrounded LLM
  path against the grounded claim-extraction path on unsupported-claim rate
  and citation accuracy - requires a real LLM key and a labeled evaluation
  set of paper claims, neither of which exist in this build.
- Human-AI collaboration ablation (Experiment 4, Section 64): requires
  actual human participants doing planning tasks with/without AI
  assistance - out of scope for an automated build session.
- Larger-n versions of the memory/critic ablations across many
  constructed (or, better, real) research scenarios to support a
  population-level claim rather than a single demonstrated mechanism.

These are documented as concrete next steps in
`17_future_research.md`, not silently dropped.
